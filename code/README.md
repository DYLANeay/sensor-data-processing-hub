# Sensor Data Processing Hub

Reads environmental sensor readings (temperature, CO₂, humidity) from several sources, runs them through a configurable chain of transformations, and sends the results to a console dashboard and a log file. Everything is set in `config.json`.

```
sources (CSV file, random generator)
   → transformation chain (unit conversion → smoothing → threshold alerts)
   → sinks (console dashboard, hub.log)
```

## Requirements

- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) (`dotnet --version` should print 8.x)

## Build, test, run

From this folder (`code/`):

```bash
dotnet build
dotnet test
dotnet run --project src/SensorHub.Application
```

- The app reads `config.json` from the current folder. Another file can be passed as argument:
  `dotnet run --project src/SensorHub.Application -- path/to/config.json`
- The dashboard redraws after every reading. Results are also appended to `hub.log` (next to `config.json`).
- With the default `delayMs` of 200 a full run takes several minutes. Stop it any time with **Ctrl+C**: every line already in `hub.log` is saved.
- A mistake in the config prints `Configuration error: ...` and the app exits with code 1.

## Configuration (`config.json`)

```jsonc
{
  "delayMs": 200,              // pause after each reading, in ms (0 = as fast as possible)
  "sources":         [ { "type": "...", "settings": { ... } } ],  // at least one
  "transformations": [ { "type": "...", "settings": { ... } } ],  // applied top to bottom
  "sinks":           [ { "type": "...", "settings": { ... } } ]   // at least one
}
```

Setting values are written **as text**: `"factor": "1.8"`, not `1.8`. Type names ignore case. Comments (`//`) are allowed. Paths are relative to `config.json`.

| Kind | `type` | Settings |
|---|---|---|
| Source | `csv` | `path` (CSV with header `timestamp,sensor_id,type,value,unit`) |
| Source | `random` | `sensorId`, `sensorType`, `unit`, `minValue`, `maxValue`, `count` |
| Transformation | `unitConverter` | `sensorType`, `fromUnit`, `toUnit`, `factor`, `offset` (optional, default 0): `new = value × factor + offset` |
| Transformation | `movingAverage` | `windowSize` (average of the last N values per sensor and type) |
| Transformation | `threshold` | `sensorType`, `warningThreshold`, `criticalThreshold` (alert above each) |
| Sink | `console` | none |
| Sink | `logFile` | `path` |

`sensorType` is one of `Temperature`, `CO2`, `Humidity`.

**Order matters:** thresholds are compared to the value at that point of the chain. In the default config the temperature is converted to Fahrenheit first, so its thresholds are in °F (80.6 °F = 27 °C).

### Examples of changes that need no code

- Kelvin instead of Fahrenheit: `unitConverter` with `"toUnit": "K", "factor": "1", "offset": "273.15"`.
- Add the second room: one more source `{ "type": "csv", "settings": { "path": "data/room-b.csv" } }`.
- Turn smoothing off: remove the `movingAverage` entry.
- Run instantly: `"delayMs": 0`.

## How it works

Sources are read **round-robin**: one reading from each source in turn, so every source appears on the dashboard from the start. Each reading goes through the transformation chain, then to every sink. When all sources are exhausted, the sinks are closed (the log file is flushed). Invalid CSV rows are reported on the error output and skipped.

| Project | Contents |
|---|---|
| `SensorHub.Core` | Shared data: `SensorReading`, `Alert`, `SensorType`, `AlertSeverity` |
| `SensorHub.Ingestion` | `ISensorSource`, `CsvSensorSource`, `RandomSensorSource` |
| `SensorHub.Processing` | `ITransformation`, `UnitConverter`, `MovingAverageSmoother`, `ThresholdAlerter`, `TransformationChain` |
| `SensorHub.Output` | `IOutputSink`, `ConsoleDashboardSink`, `LogFileSink` |
| `SensorHub.Configuration` | `ConfigLoader`, `HubConfig`, `ComponentConfig`, `SourceFactory`, `TransformationFactory`, `SinkFactory` |
| `SensorHub.Application` | `Program` (entry point), `Hub` (processing loop) |

`Hub` only knows the interfaces (`ISensorSource`, `ITransformation`, `IOutputSink`); the factories are the only place where concrete classes are named. Adding a new source or sink means one new class and one line in its factory. The architecture is documented in `../documentation/` and the UML model in `../uml/`.
